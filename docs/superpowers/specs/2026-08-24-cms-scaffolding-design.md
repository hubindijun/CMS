# CMS 通用后台脚手架项目设计文档

## 1. 项目概述

### 1.1 项目定位
通用后台管理系统脚手架，以电商业务为主线做功能演示。核心价值是提供一套开箱即用的 RBAC 权限体系 + 通用 CRUD 框架 + 电商示例模块，方便在此基础上快速开发各类后台管理系统。

### 1.2 技术栈

**后端：**
- Java 17+
- Spring Boot 3.x
- Spring Security（认证授权）
- Spring Session + Redis（分布式会话）
- MyBatis-Plus（ORM + 代码生成）
- MySQL 8.x（主数据库）
- Redis 6.x（会话存储 + 验证码缓存）
- Knife4j / Swagger UI（API 文档）

**前端：**
- Vue 3 + Vite
- TailwindCSS
- Arco Design Vue
- Vue Router（路由管理）
- Pinia（状态管理）
- Axios（HTTP 请求）

**项目结构：**
- Maven 多模块（三后端模块）
- 前端独立目录 `cms-admin-web/`，Vite 独立构建部署
- 代码生成器为独立项目，不在主项目内

**数据库版本：**
- MySQL 8.0.x（LTS，Spring Boot 3.x 默认驱动适配版本）
- Redis 6.x（生产广泛使用的稳定版本）

### 2.2 鉴权架构

**后台管理（cms-admin）：**
- 认证方式：用户名密码 + 图片验证码
- 会话管理：Spring Session + Redis（HttpSession）
- 权限控制：Spring Security + 自定义权限注解
  - 菜单级权限：路由级拦截
  - 按钮级权限：接口级拦截（`@PreAuthorize("hasPermission('xxx')")`）
- 密码加密：BCrypt

**对外接口（cms-api，预留）：**
- 认证方式：API Key / JWT（后续设计）
- MCP 服务：独立的认证机制（后续设计）

### 2.3 RBAC 权限模型

```
用户 (sys_user)
  └── 多对多 ─── 角色 (sys_role)
                    └── 多对多 ─── 权限 (sys_permission)
```

**权限类型：**
- 目录（一级菜单）：左侧菜单分类
- 菜单（二级页面）：可进入的页面
- 按钮（操作权限）：页面内的操作按钮

**权限标识规范：** `模块:功能:操作`，如 `product:list:query`、`order:refund:approve`

**超级管理员：**
- root 用户 + root 角色
- 拥有所有权限（包括后续新增的权限）
- 实现方式：判断角色编码为 `root` 时直接放行所有权限校验
- root 角色不可删除、不可修改编码

## 3. 功能模块设计

### 3.1 登录与个人中心

**登录页功能：**
- 账号密码输入
- 图片验证码（点击刷新，Redis 存储，5 分钟过期，用后即焚）
- 记住我（可选，延长 session 有效期）
- 登录失败 5 次锁定 10 分钟

**个人中心（右上角头像下拉）：**
- 个人信息查看与修改（昵称、手机号、邮箱、头像）
- 修改密码（需输入旧密码）

### 3.2 首页仪表盘

- 数据概览卡片：用户总数、商品总数、订单总数、今日销售额
- 快捷入口：常用功能跳转
- 最近登录日志（当前用户）

### 3.3 系统管理

#### 3.3.1 用户管理
- **列表页**：用户名、昵称、头像、手机号、邮箱、角色、状态、创建时间
- **查询条件**：用户名（模糊）、手机号（模糊）、状态、创建时间范围
- **操作**：新增、编辑、删除、重置密码、启用/禁用、分配角色（复选框多选）
- **新增/编辑字段**：用户名、密码（新增必填）、昵称、手机号、邮箱、头像、状态、角色
- **规则**：用户名唯一，手机号唯一，密码 BCrypt 加密

#### 3.3.2 角色管理
- **列表页**：角色名称、角色编码、描述、状态、创建时间
- **查询条件**：角色名称（模糊）、状态
- **操作**：新增、编辑、删除、分配权限（树形复选框）
- **分配权限**：树形结构展示，勾选父节点自动勾选子节点，支持半选状态
- **规则**：角色编码唯一，root 角色不可删除、不可修改编码

#### 3.3.3 权限管理
- **树形列表**：权限名称、类型（目录/菜单/按钮）、权限标识、路由地址、排序、状态
- **操作**：新增、编辑、删除
- **新增/编辑字段**：
  - 权限名称、上级权限
  - 类型（目录/菜单/按钮）
  - 路由地址（目录和菜单用）
  - 组件路径（菜单用，前端.vue 路径）
  - 权限标识（按钮用，如 `user:add`）
  - 图标、排序、状态
- **规则**：按钮必须挂在菜单下；目录和菜单可有子级

#### 3.3.4 字典管理
- **字典类型列表**：字典名称、字典编码、状态、操作
- **字典数据列表**（点击字典类型进入）：字典标签、字典键值、排序、状态
- **用途**：前端下拉选项统一数据源（性别、状态、订单状态等）
- **缓存**：字典数据加载到 Redis 缓存，提高查询性能

#### 3.3.5 登录日志
- **列表页**：用户名、IP 地址、登录地点、浏览器、操作系统、状态、提示消息、登录时间
- **查询条件**：用户名（模糊）、状态、登录时间范围
- **操作**：删除、清空

### 3.4 商品管理

#### 3.4.1 商品列表
- **列表页**：商品名称、主图、分类、价格、库存、状态（上架/下架）、创建时间
- **查询条件**：商品名称（模糊）、分类、状态、价格范围
- **操作**：新增、编辑、删除、上架/下架、查看详情
- **商品详情**：基本信息 + SKU 规格 + 库存信息 + 商品描述

#### 3.4.2 商品分类
- **树形列表**：分类名称、图片、排序、状态
- **操作**：新增、编辑、删除、排序（拖拽或数字输入）
- **规则**：支持三级分类；有子分类的不能删除；有商品的分类不能删除

#### 3.4.3 商品规格
- **规格列表**：规格名称（如颜色、尺寸）、规格值数量
- **规格值列表**（点击规格进入）：值名称、排序
- **用途**：商品 SKU 组合的基础数据

#### 3.4.4 库存管理
- **库存列表**：商品名称、SKU 规格、当前库存、预警库存、状态
- **查询条件**：商品名称（模糊）、分类、库存预警（低于预警值高亮）
- **操作**：入库、出库、查看出入库记录
- **出入库记录**：类型（入库/出库）、数量、操作前库存、操作后库存、操作人、备注、时间

### 3.5 订单管理

#### 3.5.1 订单列表
- **列表页**：订单号、会员名称/手机号、商品金额、订单金额、支付方式、订单状态、下单时间
- **查询条件**：订单号、会员名称/手机号、订单状态、下单时间范围
- **订单状态流转**：
  ```
  待付款 → 待发货 → 待收货 → 已完成
     ↓          ↓
   已取消     退款中 → 已退款
  ```
- **操作**：查看详情、发货（填写物流信息）、修改价格、关闭订单、添加备注
- **订单详情**：收货信息、商品明细、费用明细、支付记录、操作日志、状态流转时间线

#### 3.5.2 退款管理
- **列表页**：退款单号、关联订单号、会员、退款金额、退款原因、状态、申请时间
- **查询条件**：退款单号、订单号、会员、状态、时间范围
- **退款状态流转**：
  ```
  待审核 → 已同意 → 退款中 → 已完成
     ↓
   已驳回（需填写驳回理由）
  ```
- **操作**：查看详情、审核通过、审核驳回（必填驳回理由）
- **退款详情**：申请信息、订单关联、退款进度、操作记录
- **权限点**：审核通过（`order:refund:approve`）、审核驳回（`order:refund:reject`）

#### 3.5.3 订单设置
- 订单超时未付款自动取消时间（分钟）
- 发货后自动收货时间（天）
- 订单完成后可申请退款时间（天）
- 存储方式：系统配置表，可在线修改

### 3.6 会员管理

#### 3.6.1 会员列表
- **列表页**：会员昵称、头像、手机号、等级、状态、注册时间
- **查询条件**：昵称（模糊）、手机号（模糊）、等级、状态、注册时间范围
- **操作**：查看详情、启用/禁用、调整等级
- **会员详情**：基本信息、等级信息、订单统计、收货地址列表

#### 3.6.2 会员等级
- **列表页**：等级名称、等级值、升级条件（消费金额）、折扣率
- **操作**：新增、编辑、删除、排序

### 3.7 系统工具

#### 3.7.1 文件管理
- **列表页**：文件名、大小、类型、上传人、上传时间
- **查询条件**：文件名（模糊）、类型、上传时间范围
- **操作**：上传、删除、预览、下载
- **存储方式**：本地存储（首期），通过配置切换 OSS/MinIO
- **抽象设计**：`FileService` 接口 + 多种实现策略

#### 3.7.2 系统接口
- Swagger UI / Knife4j 在线文档
- 地址：`/swagger-ui.html` 或 `/doc.html`

## 5. 非功能性需求

### 5.1 性能要求
- 普通 CRUD 接口响应时间 ≤ 500ms
- 列表分页查询支持万级数据量
- 单节点支持 100+ 并发用户

### 5.2 安全要求
- 密码 BCrypt 加密存储，不可逆
- 接口权限拦截：菜单级 + 按钮级双重校验
- 登录图片验证码 + 登录失败次数限制（5 次锁定 10 分钟）
- SQL 注入防护：MyBatis-Plus 预编译
- XSS 防护：统一输入过滤器
- 会话管理：Redis 存储，支持强制下线
- 操作可追溯：关键修改操作留痕（订单日志、退款日志等）

### 5.3 可靠性要求
- 全局异常处理：统一错误响应格式
- 参数校验：JSR-380 后端校验 + 前端校验
- 幂等性：新增/修改接口防止重复提交
- 服务重启不丢失登录状态（Redis 会话）

### 5.4 可扩展性
- 模块化设计：按业务领域分包，新增模块不影响现有代码
- 文件存储抽象：`FileService` 接口，支持本地/OSS/MinIO 切换
- 字典驱动：状态类数据用字典管理
- 前后端完全分离，可独立部署和扩展

### 5.5 开发规范
- 统一返回格式：`Result<T>` { code, message, data }
- 统一分页格式：`PageResult<T>` { list, total, pageNum, pageSize }
- 统一异常码：业务异常（1xxx）+ 系统异常（5xxx）
- 代码分层：controller → service → mapper
- 实体分层：entity（数据库实体）、dto（入参传输）、vo（出参视图）

### 5.6 部署要求
- `cms-admin` 打包为可执行 JAR：`java -jar cms-admin.jar`
- 配置文件：`application.yml` + `application-dev.yml` + `application-prod.yml`
- 依赖组件：MySQL 8.x、Redis 6.x
- 前端：Vite 构建，静态资源部署到 Nginx 或 Spring Boot static 目录
